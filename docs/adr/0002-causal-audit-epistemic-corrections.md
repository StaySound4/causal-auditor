# ADR 0002: 因果审计认识论纠正（撤销早期草案中的绝对化断言）

- **状态**: Accepted
- **日期**: 2026-09-10
- **决策人**: 项目所有者授权（用户明确要求“先纠偏，再实施”）
- **取代**: 部分取代 `docs/adr/0001-causal-auditor-architecture.md` 中被本文件点名撤销的条款

## 背景

`因果/` 目录下的调研与草案（`01`–`04`）提出了一批有价值的工程方向（边界门禁、证据溯源、图算法、红队独立输入、动态报告），但同时把若干**未经证明的强断言**写成了“铁律”，并把“有测试通过”等同于“审计可靠”。这些断言若被固化为程序逻辑，会让系统用确定性代码输出错误结论，比原系统的“幻觉”更危险：幻觉可以被质疑，硬编码的偏见会被当作权威。

本 ADR 记录纠正项，并约束后续实现的判定语义。

## 被撤销或修正的断言

| 原草案断言 | 问题 | 修正后语义 |
| :--- | :--- | :--- |
| 零假设绝对优先，默认 $ATE=0$，无证据即判“无效/伪因果” | 把“证据不足”偷换为“效应为零”，违反统计学基本立场 | **证据不足是独立结论**。零假设是分析起点，不是判决结果。判决取值：`支持`/`反对`/`证据冲突`/`证据不足`/`不适用`。 |
| 口服大分子被水解 $\Rightarrow$ $\mathrm{NIE}=0$，直接判伪 | 水解程度、吸收形式、局部作用、代谢产物活性都需实测，不能由化学常识推出效应为零 | 水解与首过代谢作为**待核查的中介假设**，必须引用药代数据；未查证则标注未知。 |
| 必须界定“客观硬终点”，否则阻断 | 疼痛、功能量表等经过验证的结局在临床中合法且必要 | 结局**类型**必须说明（硬终点/验证量表/替代标志物/自报症状）；自报结局不阻断，但触发“需盲法与安慰剂对照”风险标记。 |
| 未界定“剂量/给药途径”一律阻断 | 商业、社会、行为类主张不存在给药剂量 | 必填字段**按领域**确定。物质暴露需途径与剂量；行为/商业/社会暴露需暴露定义与强度或频次。 |
| 废除豁免，缺要素必输出 Q1 卡片并附“推荐默认设定” | 部分歧义无关紧要，强行打断会制造噪音；而“默认设定”容易被静默当成事实 | 区分**实质歧义**（改变因果方向或人群）与**可记录的非实质假设**。实质歧义必须澄清，且**不得自动应用**任何默认值。 |
| 以 22 种偏误为“刚性排查清单”，可自动化全覆盖 | 偏误清单是启发式目录，多数条目无法仅由图结构判定 | 22 项为**可扩展的排查目录**：每项返回 `命中`/`不适用`/`未知`，并给出依据；`未知`是正常结果。 |
| 红队必须强行提出至少 2 条混杂替代解释与毒性 | 强迫生成会制造虚假论证，与“反幻觉”目标自相矛盾 | 红队必须**考虑**替代解释；允许结论为“未发现有力替代解释”或“证据不足”。不得为凑数编造。 |
| 严禁“可能/部分/或许”等模糊词 | 与“证据不足”这一必要结论直接冲突 | 禁止的是**用模糊词掩盖可查证的事实**。表达不确定性、置信度与证据强度时必须使用限定语。 |
| 计算“搜索饱和度 0–100%” | 命中数量与科学证据充分性无因果关系，伪指标会制造权威感 | 改为**可核验的检索元数据**：检索式、来源分布、年份跨度、去重后条目数、是否命中监管信号。明确声明这不是证据充分性评分。 |
| 图算法可判定因果识别与偏误 | 算法只对**给定图与假设**有效；真实图通常未知 | 明确算法契约：输入是**已声明的图**。结论标注“在该图假设下”。不得从一句话主张自动推断真实图。 |
| 单轮提示词 = 物理隔离 | 单上下文自回归无法提供隔离 | 单上下文模式明确标注为**非隔离**，并说明其失效模式；隔离仅在宿主提供独立子进程时成立。 |
| 未执行真实检索也可写“经检索 Cochrane 2024 显示” | 典型的脑补验证 | 未调用工具即不得声称已检索。证据条目必须带真实标识符与检索时间；无法获取即报告 `UNAVAILABLE`。 |
| 宿主能力缺失时自动降级 | 静默降级会让用户以为已审计 | 缺失能力必须**阻断并说明**，返回明确状态，不得以“尽力而为”替代。 |
| “全量测试通过 = 审计可靠” | 测试只证明代码符合断言，不证明外部事实 | 分离三类证据：**离线确定性测试**、**真实工具/宿主运行记录**、**人工复核**。三者独立报告，任一缺失不得声称完成。 |

## 对实现的约束

1. 判定结果类型必须能表达“未知/证据不足”，不得只有真/假二值。
2. 任何由外部事实支撑的结论，必须能追溯到具体的证据条目与检索记录。
3. 任何由结构推出的结论，必须能追溯到具体的图与假设集合。
4. 报告必须显式列出未解决项、能力缺失项与未执行项。
5. 禁止在代码或文档中出现无法核验的完成度声明。

## 后果

- 报告会比草案更“不干脆”，但结论可追溯、可反驳。
- 部分原本计划的自动化（如“自动判定伪科学”）被降级为“生成待核查问题”，这是正确的降级。
- `因果/` 目录下的调研文档保留为**参考材料**，其中绝对化表述不构成本仓库的规范。
