# causal-auditor v0.9.0

**A causal audit engine that says "insufficient evidence" instead of guessing.**

This is the first public release: the earlier prompt-only skill has been rewritten into a deterministic, testable engine where every conclusion is bound to either a specific evidence item or a specific graph plus assumptions.

---

## Why it exists

Most "AI fact-checkers" fail in the same three ways:

1. **They invent evidence.** A prompt asks for a literature review, no retrieval tool is bound, and the model fabricates DOIs, journals, and a "95% search saturation".
2. **They collapse uncertainty into a binary.** "Not found" silently becomes "false" — a statistical error, not a conclusion.
3. **They argue for the claim.** Autoregressive models anchor on their first sentence, so a "red team" in the same context becomes a cheerleader.

v0.9.0 addresses each with a hard mechanism rather than a prompt request.

## Highlights

| Failure mode | Mechanism in v0.9.0 |
| :--- | :--- |
| Fabricated evidence | Retrieval is a hard seam. No provider ⇒ explicit `UNAVAILABLE`. Items lacking a real identifier (PMID/DOI/regulatory number/URL) are **rejected and logged**. |
| Binary truth claims | A **five-value verdict** including `INSUFFICIENT_EVIDENCE` and `CONFLICTING`. |
| Self-serving reasoning | Red-team input is **information-shielded**: any object containing verdict/conclusion fields is rejected with a contract violation. |
| Fake precision | No "saturation percentage" — only verifiable retrieval metadata, with an explicit disclaimer that it is not an evidence-sufficiency score. |
| False balance | No forced three-tier pyramid; the report adapts and never pads a debunking to look symmetric. |
| Overclaiming | Every verdict is marked `requires review`: the engine counts evidence direction, it does not grade study quality. |

### What's inside

- **Boundary gating** — required elements are domain-driven. Clinical/nutritional claims need route and dose; behavioral/commercial/social claims need an exposure definition instead. Missing elements produce a clarification card and stop the audit; **no defaults are filled in silently**.
- **Graph kernel** — pure d-separation, collider detection (including collider descendants), minimal backdoor adjustment sets, cycle detection, latent-variable exclusion, and an explicit `SEARCH_LIMIT` state distinct from `NO_ADJUSTMENT_SET`.
- **22-pattern bias catalog** — every pattern returns `PRESENT` / `ABSENT` / `UNKNOWN` / `NOT_APPLICABLE` **with a stated basis**. `UNKNOWN` is a first-class, expected result.
- **Dual-track evidence engine** — confirmatory and falsification queries run separately; live PubMed retrieval via NCBI E-utilities with **zero third-party dependencies**.
- **Red-team contract** — conclusions are validated; citations to unknown evidence are rejected; "no alternative found" and "insufficient evidence" are legal conclusions.
- **Adaptive report** — five-value verdict, numbered citations bound to real identifiers, ASCII causal diagram, unresolved items and capability gaps.
- **Isolation proof** — isolation is *verified* from host-reported process ids, never asserted. Shared id, missing id, skipped stage, or stage failure ⇒ `isolated: false` with a reason.

## Verification

Three independent evidence classes, all required:

```bash
npm test                                                        # 109 tests (108 offline + 1 opt-in live gate)
npm run typecheck                                               # TypeScript strict mode
CAUSAL_AUDITOR_LIVE=1 node --test "test/live_pubmed.test.ts"    # real network gate
node scripts/live_probe.ts                                      # print real queries + hits
```

- **Offline tests** prove the deterministic code obeys its declared contract. They do **not** prove any external fact is true.
- **Live run records** prove retrieval actually happened and returned real identifiers. They do **not** prove the studies are good.
- **Human review** is still required for study quality and applicability.

Green tests alone do not mean the audit conclusion is correct.

Notable suites:

- `test/bias_scenarios.test.ts` — 6 end-to-end benchmark scenarios compared against an **exhaustive** expected `PRESENT` set: **0 false positives, 0 false negatives**.
- `test/dag.test.ts` — textbook d-separation cases: chains, forks, colliders, collider descendants, M-structure, latent exclusion, `SEARCH_LIMIT` vs `NO_ADJUSTMENT_SET`.
- `test/scheduler.test.ts` — the anti-fake-isolation suite: a shared process id makes isolation fail.

## Quick start

```bash
npm install

node src/cli.ts examples/request.json                                     # no retrieval, stated explicitly
node src/cli.ts examples/request.json --live                              # real PubMed retrieval
node src/cli.ts examples/request.json --replay examples/fixture.json      # offline replay
node src/cli.ts examples/request.json --replay examples/fixture.json \
  --redteam examples/redteam.json                                        # contract-validated red team
node src/cli.ts examples/request.json --prompt                            # single-turn host prompt
```

Requires Node ≥ 22 (tested on Node 24).

## Known limitations

- Keyword-based queries; non-English terms have low recall in PubMed (the engine warns).
- Falsification search is incomplete by nature — retrieval **cannot** prove "no opposing evidence exists".
- Most of the 22 biases return `UNKNOWN` when study-design information is absent. That is the honest result, not a bug.
- Backdoor adjustment search is exhaustive; > 12 candidate variables returns `SEARCH_LIMIT` (reported explicitly, never presented as "unidentifiable").
- Isolation is verified, not created — real multi-process orchestration requires a host `SubagentHost` adapter.
- Red-team conclusion generation still needs a model or a human; this repo provides the contract, validation, and prompt construction.

## 中文摘要

`causal-auditor` v0.9.0 首个公开发布版。把"这个说法可信吗"拆成可核验的步骤：边界门禁 → 图论识别 → 22 项偏误排查 → 双向证据检索 → 红队对抗 → 带缺口披露的报告。

**核心差异**：判定是**五值枚举**（含"证据不足"与"证据冲突"），不是真/假；检索是硬接缝，没有工具就写"未执行检索"，绝不编造文献；红队输入经过信息屏蔽，结论引用未知证据会被拒绝；隔离状态由宿主报告的进程标识**验证**，而非声称；报告不强制三档金字塔，不制造虚假平衡。

**验证**：109 项测试（108 项离线 + 1 项可选真实网络门禁）、TypeScript 严格模式。6 组端到端基准场景与穷举期望集比对，误报 0、漏报 0。**测试全绿不等于审计结论正确**——离线测试、真实运行记录、人工复核三者缺一不可。

**已知限制**：检索式基于关键词（非英文召回率低）；证伪检索天然不完备，无法证明"不存在反对证据"；缺少研究设计信息时多数偏误返回"未知"，这是诚实结果。
